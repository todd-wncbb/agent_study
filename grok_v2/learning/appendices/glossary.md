# Grok Build 全局术语表

本表解释跨文章反复出现的通用词。每篇文章仍保留“本篇术语表”，用于说明同一个词在当前调用链里的具体含义。

## Rust 与工程结构

| 名词 | 解释 |
| --- | --- |
| Cargo | Rust 官方构建和包管理工具，负责依赖解析、编译、测试和发布。 |
| crate | Rust 的包和编译单元；通常有自己的 `Cargo.toml`，可以是库或二进制。 |
| workspace | 用一个根 `Cargo.toml` 统一管理多个 crate 的工程。注意它也可能指 agent 正在操作的项目目录，需看上下文。 |
| manifest | 描述包名、依赖、feature 和构建目标的清单；Rust 中通常是 `Cargo.toml`。 |
| module | crate 内用 `mod` 组织的代码命名空间，通常对应一个 `.rs` 文件或目录。 |
| trait | Rust 中描述“某种类型能做哪些事情”的接口，可有多个具体实现。 |
| implementation | trait 或抽象的具体实现；阅读时应区分产品实现与测试 mock。 |
| feature | Cargo 编译期开关，可选择性启用代码或依赖。 |
| `cfg` | Rust 条件编译标记，根据平台、feature 或测试状态选择编译哪些代码。 |
| ownership | Rust 关于值由谁负责、何时移动或释放的规则；架构文档中的“状态所有权”还包含业务责任。 |
| `Arc` | 原子引用计数智能指针，让多个线程或任务共享同一个值的所有权。它本身不保证内部值可随意修改。 |
| `Mutex` | 同一时刻只允许一个执行者访问其内部数据的互斥锁。异步代码还要区分同步锁和 Tokio 异步锁。 |
| `Send` | 表示一个值可以安全地移动到另一个线程。 |
| `Sync` | 表示一个类型的共享引用可以安全地被多个线程使用。 |

## 异步与并发

| 名词 | 解释 |
| --- | --- |
| async | 函数可以在等待 I/O 等事件时暂停，让执行器去做别的工作。它不自动等于并行。 |
| future | 表示一个尚未完成、以后会产生结果的异步计算。 |
| runtime | 调度 future、提供定时器和异步 I/O 的执行环境；本项目主要使用 Tokio。 |
| Tokio task | Tokio 调度的轻量异步任务，不等于操作系统线程。 |
| OS thread | 操作系统调度的线程，创建和切换成本通常高于 Tokio task。 |
| LocalSet | Tokio 在一个线程内调度本地 future 的容器，可运行部分非 `Send` future。 |
| channel | 任务之间传消息的通道。常见 `mpsc` 是多发送者单接收者，`oneshot` 只发送一次。 |
| actor | 独占状态并通过消息逐个处理请求的运行单元。不是每个 async task 都是 actor。 |
| cancellation | 请求运行中的工作停止。需要代码主动观察取消信号并安全收尾。 |
| graceful shutdown | 停止接收新工作，同时给已有工作和资源清理留出时间的有序关闭。 |
| backpressure | 下游处理不过来时，通过有限队列、等待或拒绝来限制上游速度。 |

## Agent 与模型

| 名词 | 解释 |
| --- | --- |
| agent | 结合模型、规则、工具和状态，能多步执行任务的程序。 |
| prompt | 发给模型的输入；可能包含 system prompt、用户内容、历史、工具定义和附件。 |
| system prompt | 规定模型角色、规则和行为边界的系统级输入。 |
| session | 一次可持续、保存和恢复的交互实例。 |
| turn | 用户的一次输入到该次任务阶段性完成的逻辑回合。 |
| sampling | 向模型发起一次生成请求并消费输出的过程。一个 turn 可能有多次 sampling。 |
| token | 模型处理文本时使用的基本计量单位，不严格等于一个字或一个单词。 |
| context window | 一次模型请求最多能接收和生成的 token 范围。 |
| compaction | 把较长历史总结或裁剪成更短内容，以腾出 context window。 |
| streaming | 模型不等完整回答结束，而是逐步返回文本或结构化事件。 |
| tool call | 模型提出的结构化工具调用意图；它还需要经过校验、权限和执行。 |
| tool result | 工具执行后的结构化结果，会加入 agent 上下文供后续判断。 |
| JSON Schema | 机器可读的数据结构约束，常用于描述工具参数。 |

## 运行形态与协议

| 名词 | 解释 |
| --- | --- |
| CLI | 通过终端参数和子命令操作程序的命令行界面。 |
| TUI | 在终端字符网格中实现的交互界面。 |
| stdio | 操作系统提供给进程的标准输入、标准输出和标准错误流。 |
| headless | 不启动交互式 TUI 的运行方式。 |
| leader | 能被多个客户端发现和复用的长生命周期 Grok 进程。 |
| transport | 消息从一端到另一端使用的实际传输方式，如 stdio 或 WebSocket。 |
| protocol | 双方约定的消息格式、顺序和错误语义。 |
| ACP | Agent Client Protocol，主要连接宿主/编辑器和 agent。 |
| MCP | Model Context Protocol，主要连接 agent 和外部工具服务。 |
| RPC | Remote Procedure Call，把跨进程或跨机器消息包装得像调用一个过程。 |
| relay | 在两个端点之间转发消息或连接的中间层。 |
| PTY | 伪终端，让程序可以像连接真实终端一样控制交互式子进程。 |

## 设计与扩展

| 名词 | 解释 |
| --- | --- |
| composition root | 应用最外层创建并连接具体组件的位置。 |
| IoC | 控制反转：组件不自己决定并创建所有依赖，而由外层把实现交给它。 |
| dependency injection | 依赖注入：实现 IoC 的常见方法，通过构造参数、trait object、回调等传入依赖。 |
| hook | 在既定流程中预留的扩展接入点。需要结合上下文区分 Git hook、生命周期 hook、函数回调等。 |
| IoC hook | 外层用来安装可替换实现的接入点。本项目 minimal pager 的安装逻辑是一个例子。 |
| adapter | 把一种接口或数据格式转换成另一种的组件。 |
| bridge | 连接两个子系统并负责转换、转发或协调的组件。 |
| registry | 按名称或类型登记实现、之后可查询的集合。 |
| dispatch | 根据名称、枚举或消息类型选择具体处理者。 |
| plugin | 可独立发现或安装的扩展包，具体能力取决于插件系统。 |
| hook script | 在某个生命周期事件发生时执行的脚本，与 Rust 回调 hook 不一定是同一机制。 |

## 安全、状态与可靠性

| 名词 | 解释 |
| --- | --- |
| sandbox | 用操作系统机制限制进程可访问资源的隔离环境。 |
| permission | 程序层面对某个操作是否允许、拒绝或询问用户的决策。 |
| trust | 对某个文件夹或来源是否可信的更上层判断，不等同于每次工具调用都自动允许。 |
| side effect | 修改函数外部世界的行为，如写文件、执行命令或发网络请求。 |
| persistence | 把状态写入磁盘或远端，使进程退出后仍能恢复。 |
| event | 表示“发生了什么”的结构化记录或运行时通知。 |
| replay | 按顺序重放过去事件以重建状态。 |
| journal | 追加记录操作或事件的持久日志。 |
| checkpoint | 一个可以回到的已知状态点。 |
| retry | 一次操作失败后按策略再次尝试。 |
| idempotent | 同一操作执行多次与执行一次的有效结果相同。 |
| telemetry | 为观察系统而收集的日志、指标和 trace。 |
| trace | 记录一个请求跨组件经过哪些操作以及耗时的关联数据。 |
| metric | 可聚合的数值测量，如次数、延迟和错误率。 |
| fixture | 测试预先准备的输入数据或环境。 |
| mock | 可控制的假实现，用来替代真实网络、模型或文件服务。 |
| snapshot test | 把输出与保存的标准快照比较的回归测试。 |
